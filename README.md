# PEWS — Project Early Warning System

Risk intelligence over the central sector infrastructure portfolio monitored under
PAIMANA. The system reads the monitoring data MoSPI already collects and flags projects
whose expenditure is detaching from their physical progress — before the official record
registers a problem.

**Current state: the frontend is complete. The ML pipeline and API are not built yet.**
See [Status](#status) below for exactly what that means.

```bash
cd web
npm install
npm run dev       # http://localhost:5173
```

---

## What a judge sees

| Screen | The question it answers |
|---|---|
| **Portfolio** | Where is risk concentrated across ₹42.78 lakh crore and 1,981 projects? |
| **Watchlist** | Which projects need attention this cycle — by probability, or by rupees at stake? |
| **Project detail** | Why is this one project dangerous, and how certain is the model? |
| **Time Machine** | How long before the official record did the signal exist? |
| **Evidence** | Was the method tested, or just asserted? |
| **Upload & rescore** | Does this fit the existing monthly monitoring cycle? |
| **Assistant** | Can an analyst interrogate the portfolio without writing a query? |

**Demo path:** Portfolio → Watchlist (flip the exposure toggle) → `PRJ-004217` →
Time Machine (press **Replay from start**) → Upload → Assistant → Evidence.

## Status

The frontend is finished and every control works. It is currently served by
**deterministic fixtures**, not by a trained model.

| Layer | State |
|---|---|
| React SPA, 7 screens, all interactions | **Built** |
| Typed API client against the §13 contract | **Built** — 14 endpoints typed in `web/src/api/types.ts` |
| Fixture provider (`VITE_USE_MOCK=true`) | **Built** — `web/src/api/mock.ts` |
| `ml/` — generator, leakage guard, LightGBM, SHAP, ablation, replay precompute | **Not built** |
| `api/` — FastAPI process | **Not built** |

The fixtures in `web/src/mocks/` are generated by `npm run fixtures`. They are calibrated
to the published portfolio aggregates and shaped to the scenario specifications, so the
UI can be built and demonstrated ahead of the model. **They are not model output.** When
the pipeline lands, set `VITE_USE_MOCK=false` and the same components read the live API
with no changes — that is the whole reason the mock sits behind the typed client rather
than inside the components.

Nothing in the UI holds a literal figure. Every number on screen comes from an API-shaped
response.

## Real vs simplified

Reproduced from the technical approach, and stated on stage before it is asked.

| Component | Prototype | Production |
|---|---|---|
| Frontend | **Real** — 7 screens, all functional | Same, plus role-based views |
| Backend | Planned: one FastAPI process, in-memory pandas | Containerised, replicated |
| AI model | Planned: LightGBM genuinely trained, artefacts committed | Per-sector families, monthly retrain with a promotion gate |
| Explanations | Planned: genuine `TreeExplainer` output | Same |
| Baselines | Planned: naive, OLS, logistic, Weibull AFT — genuinely fitted | Survival models promoted to primary |
| Dataset | **Synthetic**, PAIMANA schema, calibrated to published aggregates | Live PAIMANA / OCMS panel |
| Database | **None** — Parquet + JSON, pandas in memory | PostgreSQL 16, partitioned |
| Authentication | **Not implemented** | NIC SSO, ministry-scoped row-level security |
| Assistant | **Real but templated** — deterministic, non-generative | Optional local LLM narration over the same grounded results |
| External services | **None** — zero network calls at demo time | PAIMANA API, notification gateway |

The data is synthetic. The modelling — once built — is real. The interface never presents
the first as the second: the header carries a permanent provenance chip, and the Evidence
page leads with its limitations rather than burying them.

## Calibration

`npm run fixtures` reproduces the published figures exactly, and `npm run check` asserts
them. Both run offline.

| Anchor | Target | Produced |
|---|---|---|
| Ongoing projects | 1,981 | 1,981 |
| Ministries / sectors | 17 / 22 | 17 / 22 |
| Original cost | ₹37.13 lakh crore | ₹37.13 lakh crore |
| Revised cost | ₹42.78 lakh crore | ₹42.78 lakh crore |
| Aggregate overrun | 15.2% | 15.23% |
| Expenditure | ₹20.36 lakh crore | ₹20.36 lakh crore |
| Critical band | 214 | 214 |
| Exposure at risk | ₹3.1 lakh crore | ₹3.10 lakh crore |

`npm run check` also guards the four demonstration scenarios — including that
`PRJ-004217` crosses the alert threshold in **Nov 2024** against an official revision in
**Oct 2025**, giving **11 months** of lead time. If a fixture regenerates wrong, the
check fails rather than the demo.

## Design decisions worth knowing

- **Warm neutral ground rather than slate-50.** A deviation from the specified palette;
  the cooler default reads as a framework template under projection. Risk band colours
  are unchanged and always carry a text label, never colour alone.
- **The Time Machine opens on the completed replay,** not at month zero. Landing on an
  empty chart is a poor first impression for the screen the submission rests on, and a
  presenter narrates better by showing the finding, then rewinding to earn it.
- **Money is formatted in crore and lakh crore only.** There is no "thousand crore" unit
  in MoSPI reporting.
- **Charts are hand-built where a library would lose.** The risk trajectory needs
  clip-based reveal, per-segment colouring at the threshold crossing, and an annotated
  lead-time bracket; Recharts handles the divergence and calibration charts, where it
  earns its place.
- **The SHAP panel is a ranked contribution view, not a waterfall dump.** It separates
  what raises risk from what lowers it and states each in plain language. The
  contributions are additive and reconstruct the score exactly — asserted in `npm run check`.
- **Filter state lives in URL search params,** so a mid-demo refresh restores the view.

## Layout

```text
web/
├── scripts/
│   ├── make-fixtures.mjs      # deterministic fixtures, calibrated to A3
│   └── check-fixtures.mjs     # 55 assertions: aggregates + 4 demo scenarios
└── src/
    ├── api/                   # types.ts (wire contract) · client.ts · hooks.ts · mock.ts
    ├── components/            # ui.tsx (primitives) · charts.tsx
    ├── lib/format.ts          # formatCrore, band tokens, CSV export
    ├── mocks/                 # generated — not committed as model output
    └── pages/                 # one file per screen
```

`npm run check` after any change to the generator. It is the guard that the demo still
tells the story it claims to.

## Known gaps

- `ml/` and `api/` are not built; the frontend runs on fixtures until they are.
- Alert acknowledgement, what-if sliders, and the peer-cohort deep link are not implemented.
- `projects.json` is 4.5 MB and statically imported, which inflates the dev bundle. It
  disappears once the API serves data, so it is not worth code-splitting now.
- Optimised for 1366×768 and 1440×900. There is no mobile layout.
